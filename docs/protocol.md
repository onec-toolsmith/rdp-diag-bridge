# Протокол обмена, версия 1

MCP-сервер и агент обмениваются файлами JSON в UTF-8 без BOM (читать нужно с допуском BOM). Время протокола – UTC
`ГГГГ-ММ-ДДTчч:мм:сс.мсZ`; даты внутри результатов – местное время удаленного компьютера без зоны.

## Каталоги

Корень у MCP – `RDP_DIAG_BRIDGE_DIR` (по умолчанию `C:\RdpDiagBridge`). Агент берет корень из `--dir`, иначе
родительскую папку, если сам лежит в `<корень>\agent`, иначе `\\tsclient\C\RdpDiagBridge`.

```
<корень>\
  .clock                 проба часов: MCP пишет файл и берет его время изменения как текущее
  agent\RdpDiagBridge.exe  копия агента для запуска из RDP-сеанса
  <сеанс>\               8 шестнадцатеричных символов, заводит агент, удаляет при закрытии
    session.json         сведения и сердцебиение (агент, раз в 2 с и при смене состояния)
    in\<id>.json         новые команды (MCP пишет <id>.tmp и переименовывает)
    work\<id>.json       команда у агента: ждет решения пользователя или выполняется
    work\<id>.cancel     просьба MCP прервать команду или отозвать запрос
    out\<id>.json        ответ (агент пишет <id>.json.tmp и переименовывает)
```

Сеансом считаются только папки с именем из 8 hex. Удаление – только известных файлов (`.json`, `.tmp`, `.cancel`,
`session.json`, `stop`) и пустых папок, без рекурсивного удаления. MCP удаляет каталоги сеансов, молчащих больше суток.

## session.json

`protocol`, `agentVersion`, `session`, `path`, `computer`, `domain`, `user`, `elevated`, `os`, `clientName` и
`rdpSession` (переменные CLIENTNAME и SESSIONNAME), `started`, `heartbeat` (часы агента), `state` (`ready`, `busy`,
`awaiting` – ждет решения пользователя, `paused`), `busyCommand`, `busyType`, `progress`, `allowCode`, `confirm`
(`code`, `all`, `none`), `headless`, `commandsDone`, `pid`.

Возраст сердцебиения MCP считает по времени изменения `session.json` против пробы `.clock`: оба времени ставит файловая
система компьютера с MCP, расхождение часов не мешает. Команда выполняется в отдельном потоке, поэтому сердцебиение
идет и во время долгих команд; тишина дольше 10 с – агент не отвечает. Разница между `heartbeat` и временем изменения
файла – расхождение часов удаленного компьютера.

## Команда

```json
{"protocol": 1, "id": "20261110T170001494-4800", "type": "events", "ttlSec": 90,
 "sentUtc": "2026-11-10T17:00:01.494Z", "params": {"log": ["System"], "hours": 24}}
```

`type`: `ping`, `health`, `sysinfo`, `events`, `processes`, `services`, `disks`, `perf`, `network`, `nettest`,
`software`, `tasks`, `files`, `onec`, `powershell`. Параметры – как у инструментов MCP, имена в camelCase
(`max_message` → `maxMessage`).

Агент берет команды по одной в порядке имен, переносом из `in` в `work`. Не удалось перенести – команду уже снял MCP.
MCP снимает команду, которую агент не взял за время ожидания вызова. Срок `ttlSec` агент считает по своим часам от
момента, когда впервые увидел файл: команда, пролежавшая дольше `ttlSec + 5` с, получает ответ `expired`.

`powershell` без разрешения в окне агента сразу получает `rejected`. Команда, требующая подтверждения (режим `code` –
только `powershell`, `all` – любая), остается в `work`, `state` – `awaiting`, пока пользователь не решит. `work\<id>.cancel`
отзывает такой запрос или прерывает выполняемую команду (процесс PowerShell снимается).

## Ответ

```json
{"protocol": 1, "id": "...", "type": "events", "status": "ok", "receivedUtc": "...", "finishedUtc": "...",
 "result": {}, "warnings": [], "durationMs": 120}
```

`status`: `ok`, `error` (`error`, `errorDetails`), `rejected`, `denied` (пользователь отклонил; `comment` – его
комментарий), `cancelled`, `expired`. Комментарий пользователя при разрешении приходит в `warnings`.
